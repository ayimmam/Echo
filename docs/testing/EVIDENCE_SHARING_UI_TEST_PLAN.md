# Evidence, reproducibility, sharing and UI acceptance delta

Prepared 2026-10-06 for [ADR-018](../adr/018-measurement-evidence-and-sharing.md). **All product cases NOT RUN.** Plans/contracts only; no test implementation is added. Use synthetic identities/records and disposable environments for fault cases. Existing device, cohort, security and research-access suites remain required.

Record case ID, commit/schema/model/policy/consent versions, fixture seed/hash, device/runtime, expected/actual result, pass/fail/blocked and restricted redacted evidence path. A missing prerequisite is blocked. Never inject faults or purge real participant data during testing. Sources/rationale: [focused review](../research/FOCUSED_ARCHITECTURE_REVIEW.md).

## Measurement and release policy (G1/G2; field release at G5)

| ID | Procedure | Required outcome |
|---|---|---|
| EVID-01 | Pass identical numeric measurements with synthetic, model, observer, absent and unknown origins through display, aggregate, sync and research adapters. Supply illegal available/value/reason combinations and non-finite values. | Origin stays explicit; unknown/malformed records fail closed. Synthetic/observer values cannot become field model results; unavailable never becomes zero. Observer results remain in the approved research workflow. |
| EVID-02 | Use a model declaring the correct cohort but no approved release. Then vary artifact hash, label/spec, feature/postprocess hash, metric, language and required context one at a time against a synthetic released manifest. | Exact supported approved combinations alone enable the metric. Client-provided approval/availability flags cannot bypass server validation. No real release is seeded just to make fixtures pass. |
| EVID-03 | Withdraw a release, expire its policy, update policy after a cached report exists and reconnect an offline device holding older evidence. | Current policy suppresses affected display/export/aggregation without rewriting sealed provenance. Offline behavior reflects the last valid policy and expiry; server rejects stale admissions. No claim of instantaneous offline remote revocation. |
| EVID-04 | Build a week with three eligible sessions but only one available/released I-5, mixed model/spec/language releases and mixed observer/model origins. | Thresholds/counts apply separately per metric. Incompatible records are not averaged; I-1 success cannot unlock I-5. Unknown/withdrawn evidence produces a clear reason. |
| EVID-05 | Migrate current demo/legacy records, including unknown source and the historical five-class schema. Repeat migration and restore an older backup. | Explicit synthetic origins for known fixtures; unverified legacy origin remains unavailable. No silent coarse-label conversion, invented evidence or migration-based release approval. |
| EVID-06 | Compare blinded live aggregate forms and model summaries under VALID-01. Attempt to use observer agreement, a completed JSON manifest or a high confidence value alone as a pedagogical release. | Acoustic agreement, activity context and usefulness remain distinct claims; observer repeatability and cohort gates still apply. No quality/equity/learning score or automatic card prescription. |

## Reproduction and streaming (G2/G3)

| ID | Procedure | Required outcome |
|---|---|---|
| REPRO-01 | Rebuild from a clean environment using pinned source/dependencies, approved asset hashes/config/seed and documented commands. Re-run Python/Kotlin policy/math fixtures and export comparisons. | Deterministic outputs agree; declared floating-point/export tolerances pass; missing/changed assets/config fail visibly. Training packages do not enter web/mobile deployment bundles. |
| REPRO-02 | Use permitted synthetic/existing fixtures at chunk boundaries, warm-up and final partial chunks; compare declared streaming/batch behavior; interrupt, reset and restart the stateful runtime with low/high decision thresholds. | No duplicate/missing owned ticks, stale state across sessions or incomplete speech termination. Missing capture stays missing. Changes in valid streaming lookahead are accounted for rather than demanding unjustified batch equality. No new field recordings retained. |
| REPRO-03 | On the same candidate release, measure accuracy/coverage, whole-pipeline RTF/latency, RSS and battery using the existing phone/endurance profile. Include resource contention and noise/placement strata where authorised. | Artifact/build/run manifest binds all results; unsupported conditions and sample counts explicit. Desktop/MCU/vendor benchmarks do not count as Android results. Existing technical targets remain; no unmeasured claim of improvement. |

## Sharing defaults and authorisation (before each applicable G4)

| ID | Procedure | Required outcome |
|---|---|---|
| SHARE-01 | Fresh enrolment: both preferences ON. Test no authorisation, private-only authorisation, research-only authorisation, both active, expired/revoked scope, and unavailable destinations. Save and discard records. | Only saved, allowlisted records covered by that purpose's prior authorisation can transfer automatically. No live/intermediate/discarded data sent. One ready purpose does not imply the other is ready. Default ON or absence of opt-out never creates a consent receipt. |
| SHARE-02 | Turn private sync OFF while research remains ON, then reverse the combination. Exercise fresh save, retry, process death and resume. | Each purpose's durable setting controls only its data outbox. No private upload while private sync OFF; independently authorised research can continue, clearly explained. No coupling of local reports/cards to participation. |
| SHARE-03 | Turn research OFF while offline, during a queued send, after server commit before ACK and during retry. Restart app and restore old client state; then reconnect. | Immediate local stop, unsent research queue cleared, withdrawal durably pending; control request remains sendable. Server-known revocation wins over stale uploads and removes admitted restricted contributions under policy. In-flight uncertainty is reconciled, never falsely reported as deletion complete. |
| SHARE-04 | Upgrade users with ON, OFF, withdrawn and unknown legacy state. Reinstall/recover, switch accounts and re-enable after withdrawal. | Never flip an existing OFF/withdrawn choice to ON. Unknown state blocks pending recovery. Re-enable cannot revive revoked consent/erased records; defaults are prospective and new-enrolment-only. No silent historical backfill. |
| SHARE-05 | Try the private app credential on the research intake and reverse it; forge study code/owner/cohort, replay same ID across purposes and mutate retry payload. | Audience/purpose/ownership enforced at server transaction. Independent ACK/idempotency keys; mismatches/conflicts rejected without revealing another person's record. No researcher access to private reports. |
| SHARE-06 | Add audio/base64 media, features/posteriors, fine timeline, child identity, exact-date R1 fields, local card/exclusion state, private report screenshots and observer values to the automatic model projection. | Strict purpose allowlists reject extras. Required enrolment/linkage remains R0/control metadata; R1 admitted representation stays minimal. Observer forms are independently locked and not generated from model output. |
| SHARE-07 | Delete private shared summaries; remove a research session; withdraw research; withdraw/delete everything; restore backups before each deletion and replay journals. | Scope clearly explained and respected; sync OFF alone does not claim old private copies removed. Research OFF follows withdrawal policy. Pending/acknowledged status honest; no data resurrection. Published anonymous R2 limits explained. |
| SHARE-08 | Change the approved study schema/purpose/endpoint, expire the enrolment or lose institutional/provider readiness. Inject a failed intake and an unauthorised destination fallback. | New scope requires matching authorisation; purpose blocks on expired/unknown permission or failed required readiness. No foreign/email fallback, whole-report export or unlogged expansion. Logs contain only permitted metadata. |

## Simpler navigation and comprehension (before field UI release)

| ID | Procedure | Required outcome |
|---|---|---|
| UI-01 | From fresh/returning use, complete readiness → lesson → pause/resume → finish → context → save/discard using Today/Reflection/Settings. Access history and chosen card. | Three top-level destinations, one primary action per stage; history within Reflection. Unknown context is permitted and suppresses unsupported measures. Capture state and interruption remain unmistakable. |
| UI-02 | Ask development participants to find and turn OFF each purpose from first use and from a running app, including offline/large-text/screen-reader use. | Controls only in clearly labelled Settings and reachable within the planned tap budget; OFF takes effect without login, network or confirmation friction. First-use disclosure and Settings distinguish recipients, purposes and deletion consequences. Measure success/errors against predeclared targets; no false consent inference. |
| UI-03 | Show released, unreleased, missing-context, low-coverage and wholly synthetic examples in each supported locale. Use structured comprehension questions. | Users can distinguish illustrative/unsupported results from supported acoustic summaries. No implied ideal ratio, quality/equity score or missing=zero. No invented translations or hidden demo status. |
| UI-04 | Save a summary under each sharing state; change local reflection exclusion; remove a research session in Settings; inspect counters/statuses and restored UI state. | Private sync, research contribution, reflection exclusion and deletion are visibly distinct. Simplification does not hide pending/failed sharing or suggest exclusion automatically withdraws research. |

Default owners: Sys for policy, transport, migration and UI implementation; ML for model manifests/reproduction; Lead/custodian for authorisation, research admission/withdrawal; teacher/native-language reviewers for comprehension. Freeze targets before held-out use. Manual forms can satisfy appropriate research-data procedures, but cannot pass the automatic SHARE cases.
